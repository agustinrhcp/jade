A functional compilation layer for the Ruby you already have.

Write the parts that deserve types in a statically typed functional language. Compile them to Ruby you'd have written yourself, and call them from the app you already have.

one gem · per-module · the compiled Ruby is yours

shapes.rb

        
module Shapes
  extend self

  Circle = Data.define(:_1) do
    def circle?; true; end
    def rectangle?; false; end
  end

  Rectangle = Data.define(:_1, :_2) do
    def circle?; false; end
    def rectangle?; true; end
  end

  module Internal
    extend self

    def area(shape)
      case shape
      in Shapes::Circle(r) then ((3.14159 * r) * r)
      in Shapes::Rectangle(w, h) then (w * h)
      end
    end

    def describe(shape)
      case shape
      in Shapes::Circle(_) then "circle"
      in Shapes::Rectangle(_, _) then "rectangle"
      end
    end
  end

  def self.area(*)
    raise Jade::Interop::NotExposed.new(module_name: "Shapes", function_name: :area, hint: "argument 1 of type Shape has no Decodable instance")
  end

  def self.describe(*)
    raise Jade::Interop::NotExposed.new(module_name: "Shapes", function_name: :describe, hint: "argument 1 of type Shape has no Decodable instance")
  end
end

module Pipelines
  extend self

  module Internal
    extend self

    def safe_divide(a, b)
      case (b == 0)
      in true then Jade::Maybe::Nothing[]
      in false then Jade::Maybe::Just[(a / b)]
      end
    end

    def shout(words)
      words.map(&Jade::Runtime.intr('String.to_upper')).join(" ")
    end
  end

  def self.safe_divide(a, b)
    Internal.safe_divide(
      Jade::Interop::Boundary.integer("Int", a),
      Jade::Interop::Boundary.integer("Int", b),
    ).then { it.is_a?(::Jade::Maybe::Just) ? it._1 : nil }
  end

  def self.shout(words)
    Internal.shout(Jade::Interop::Boundary.list_of(::String, "List(String)", words))
  end
end

module Records
  extend self

  Person = Data.define(:name, :age, :email)

  module Internal
    extend self

    def birthday(person)
      person.with(age: (person.age + 1))
    end
  end

  def self.decode_person(value)
    Jade::Interop::Boundary.hash("Person", value).then do |h|
      ::Records::Person[
        Jade::Interop::Boundary.string("String", h["name"]),
        Jade::Interop::Boundary.integer("Int", h["age"]),
        Jade::Interop::Boundary.string("String", h["email"]),
      ]
    end
  end

  def self.encode_person(p)
    { "name" => p.name, "age" => p.age, "email" => p.email }
  end

  def self.birthday(person)
    encode_person(Internal.birthday(decode_person(person)))
  end
end

Four things the compiler guarantees.

    

      

        
Absence

        
Maybe instead of nil

        
Absence is a type, and errors are values. No NoMethodError on nil, ever.

        
def withdraw(balance: Int, amount: Int) -> Result(Int, String)
  amount > balance ? Err("insufficient funds") : Ok(balance - amount)
end

      

      

        
Inference

        
Inference, not annotation

        
Annotate the signature; the compiler works out the rest.

        
def shout(words: List(String)) -> String
  words
    |> List.map(String.to_upper)
    |> String.join(" ")
end

      

      

        
Records

        
Records, updated structurally

        
Field access and update are expressions, and the result keeps its type.

        
def birthday(user: User) -> User
  { user | age: user.age + 1 }
end

      

      

        
Deriving

        
Instances derive

        
Eq, Show, Encodable and Decodable
          come free for structs and unions.

        
struct User = {
  name: String,
  age: Int
}

      

    

  






  

    

      
Add a variant, and every case that forgot it stops compiling.

      
The check is structural — the compiler names the cases you're missing,
        not just the line.

Nothing reaches the outside world without saying so.

    
Jade has no implicit side effects. Every call out to Ruby is
      declared in a uses block, takes a Task return type, and
      doesn't run until something runs it — so a function's signature tells you whether
      it does IO.

    

      

        
declare it in Jade

        
uses Mailer with
  deliver : String -> Task(Bool, String)
end


def run(email: String) -> Task(Bool, String)
  deliver(email)
end

      

      

        
implement it in Ruby

        
module Mailer
  extend Jade::Port

  task :deliver do |t, email|
    t.ok(Mail.welcome(email).deliver)
  end
end

      

      

        
nothing runs until you run it

        
task = Signup::Internal.run('ada@example.com')  # nothing has happened
task.run                                        # => Ok(true)

Signup.run('ada@example.com')                   # => ["ok", true]
Signup.run!('ada@example.com')                  # => true, raises on err

      

    

    
Because effects are values, tests stub them without touching
      the network — there are RSpec matchers for it.

  






  

    
A typed edge, not a leaky one.

    
Arguments are decoded on the way in and encoded on the way out.
      Ruby sees ordinary hashes, strings and numbers — never Jade's internal
      representation — and Jade never sees a value that didn't typecheck.

    

      

        
generated, not hand-written

        
def self.decode_person(value)
  Jade::Interop::Boundary.hash("Person", value).then do |h|
    ::Records::Person[
      Jade::Interop::Boundary.string("String", h["name"]),
      Jade::Interop::Boundary.integer("Int", h["age"]),
      Jade::Interop::Boundary.string("String", h["email"]),
    ]
  end
end

def self.encode_person(p)
  { "name" => p.name, "age" => p.age, "email" => p.email }
end

      

      

        
when Ruby lies

        
task :raw_fetch do |t, id|
  t.ok({ name: "Paul" })   # oops — missing :id
end

Users.fetch(1)
# => raises Jade::Interop::DecodeError:
#    Port returned a value that failed to decode at value:
#    missing field `id` ({name: "Paul"})

      

    

    
A port returning the wrong shape is a bug, not a runtime
      condition — the boundary raises rather than pass a malformed value inward.

    
Not every function can cross. A function is callable
      from Ruby only when all of its parameters are Decodable and its return
      type is Encodable — one that isn't still compiles, and its
      Internal form still works, but the public method raises
      NotExposed naming the type that disqualified it. That's what the
      collapsed wrappers under the diptych are.

    
For JSON that isn't a boundary crossing,
      Decode and
      Encode are
      ordinary composable pipelines, and both auto-derive for structs.

  






  

    
It goes in the app you already have.

    

      

        
Per module.

        
Point Jade at a source root and require modules by name. Each
          .jd compiles to .jade/build/<module>.rb on first
          require, and only when the source changed. There is no "Jade app."

      

      

        
Ordinary constants on the Ruby side.

        
A compiled module is a module. Signup.run(email) is just a method
          call — nothing to boot, no context to thread.

      

      

        
One gem.

        
jade-lang, which depends on base64 and nothing else.

      

      

        
You can leave.

        
The compiled Ruby is the deliverable — readable, in your tree, under your version
          control. Drop the gem and you keep the output.

      

    

  






  

    
The whole toolchain is one command.

    

      

        
jade check [file...]      # type-check; exits 1 on errors, generates nothing
jade fmt [-i|-c] [file]   # format .jd source (stdin or file)
jade lsp                  # language server over stdio
jade q hover FILE:L:C     # headless JSON queries — hover/defn/refs/symbols

        
$ jade q api List.fold
{
  "name": "fold",
  "qualified_name": "List.fold",
  "kind": "function",
  "signature": "List.fold : (List(a), b, (b, a) -> b) -> b"
}

      

      

        

          
In your editor.

          
A language server ships in the box — type errors, inferred types,
            jump-to-definition in anything that speaks LSP. jade fmt is
            deterministic and idempotent; wire it to a pre-commit hook.

        

        

          
For coding agents.

          
jade q answers the same questions as one-shot JSON,
            so a tool that doesn't speak LSP can still ask. jade q api reads
            signatures straight from the compiler's registry, so the answer can't drift
            from the compiler.

Early and experimental — being tried
      out on small projects. In progress: Comparable derivation for user types,
      partial record types in signatures, a stable REPL.

    
Not great for: throwaway scripts, libraries you ship to
      other Ruby projects, and performance-critical hot paths.
